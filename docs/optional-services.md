# Optional services

The LinkedIn workflow does not use these. They are kept for other workflows and only start when you ask for their profile.

## SearXNG (web search)

```bash
docker compose --profile search up -d
```

| From | URL |
| --- | --- |
| Other containers (n8n) | `http://searchbox:8080` |
| The server itself | `http://127.0.0.1:8080` |

`SEARXNG_SECRET` comes from `.env` (generated by pre-setup). Earlier versions of this repo committed a fixed secret in `docker-compose.yaml`; if you used that, the new generated value replaces it.

n8n needs JSON output. On first start SearXNG writes `searxng/settings.yml`; make sure it contains:

```yaml
search:
  formats:
    - html
    - json
```

Then `docker compose --profile search restart searchbox` and test:

```bash
curl -sS "http://127.0.0.1:8080/search?q=kubernetes&format=json" | head -c 300
```

HTTP `403` means JSON is not enabled or the limiter is rejecting requests. Check `docker compose logs --tail=100 searchbox`.

## n8n Sandbox (AI Assistant code sandbox)

Three services: `sandbox-certs` (one-shot, creates mutual-TLS certificates in `sandboxtls/`), `sandbox-api` and `sandbox-runner-1` (privileged Docker-in-Docker). Versions are pinned at `1.9.0`.

The runner is privileged. Run it only on a host where that is acceptable, and never publish its ports.

### Configure

Uncomment the sandbox block in `.env` and generate each value with `openssl rand -hex 32`:

| Variable | Must equal |
| --- | --- |
| `SANDBOX_API_KEYS` | `N8N_SANDBOX_SERVICE_API_KEY` |
| `SANDBOX_API_RUNNER_REGISTRATION_TOKEN` | `SANDBOX_RUNNER_REGISTRATION_TOKEN` |
| `SANDBOX_API_RUNNER_API_KEY` | `SANDBOX_RUNNER_API_KEYS` |

Use a different value for each pair.

```bash
docker compose --profile sandbox up -d
docker compose ps -a sandbox-certs        # Exited (0) is expected
find sandboxtls -maxdepth 3 -type f
```

In n8n's AI Assistant / code sandbox settings choose **n8n Sandbox**:

- Service URL: `http://sandbox-api:8080/`
- API key: the value of `SANDBOX_API_KEYS`

Do not use `localhost`, a host port, or the task runner broker `http://n8n:5679`; that is a different component.

### Troubleshooting

```bash
docker compose ps -a sandbox-api sandbox-runner-1
docker compose logs --since=10m sandbox-api sandbox-runner-1
```

Compare paired secrets without printing them; the hashes must match:

```bash
docker compose exec sandbox-api sh -c 'printf "%s" "$SANDBOX_API_RUNNER_API_KEY" | sha256sum'
docker compose exec sandbox-runner-1 sh -c 'printf "%s" "$SANDBOX_RUNNER_API_KEYS" | sha256sum'
docker compose exec sandbox-api sh -c 'printf "%s" "$SANDBOX_API_RUNNER_REGISTRATION_TOKEN" | sha256sum'
docker compose exec sandbox-runner-1 sh -c 'printf "%s" "$SANDBOX_RUNNER_REGISTRATION_TOKEN" | sha256sum'
```

| Error | Check |
| --- | --- |
| `Invalid url` | Service URL is `http://sandbox-api:8080/` |
| HTTP `401` from `/sandboxes` | Key in n8n equals `SANDBOX_API_KEYS` |
| `no sandbox runners are registered or available` | Runner logs, registration token pair, runner health |
| `invalid api key` during `runner control create` | `SANDBOX_API_RUNNER_API_KEY` equals `SANDBOX_RUNNER_API_KEYS` |
| `tls: bad certificate` | Both services use the same `sandboxtls/` CA; SAN names `sandbox-api` and `sandbox-runner-1` |
| Bridge netfilter error from the runner | `sudo modprobe br_netfilter` on the host; check nested Docker support on RHEL 8 |

Never disable TLS verification to work around a certificate error. Regenerate certificates only with both API and runner recreated together.
